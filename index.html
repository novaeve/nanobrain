nanoBrain

nanoBrain 是什么

nanoBrain 是一个让 LLM 在受控实验中演化虚拟细胞模型的系统。LLM 提出候选模型：架构、目标函数、训练配方和少量 PyTorch 插件代码；nanoBrain 负责校验候选、在隔离环境中从随机初始化训练、用同一套评估流程打分、按固定门槛决定是否晋级，并保存每一步的证据，包括失败和没有晋级的候选。

它的核心规则是：定义是开放的，演化是冻结的。演化开始之前，数据、任务、指标、对手和搜索空间都由使用者定义，nanoBrain 提供基础设施；一旦冻结并开始演化，这些就锁死，任何改动都意味着另一个 campaign。

nanoBrain 是 Brain World Model 的实验场：新的模型设计先在这里用有限预算、可复现的方式被验证或否定，再决定是否投入更大规模的训练。

开放的部分

一个 campaign 的全部选择写在一个 TOML 文件和一份给 LLM 的说明里：数据、目标、指标、预算、门槛、搜索空间。这部分代码很少，人可以直接读懂。

封死的部分

校验器、代码白名单、沙箱、GPU 调度、谱系记录、晋级门槛和冻结机制。这部分代码很多，每一条保证都有对应的测试。

生命周期

阶段谁来做能改什么命令或文件
定义人数据、任务、指标、对手、预算、门槛、搜索空间、给 LLM 的说明campaigns/<id>/campaign.toml

退役人与工具旧分支、旧目录只有在证明内容已完整保存后才能删除scripts/retire_check.py

每次启动和续跑都会核对冻结锁文件：没有冻结，或任何被锁定的文件、数据发生变化，都会拒绝运行并列出变化的内容。同一个 campaign id 不能重新冻结成不同的内容。

当前 campaign：以 Cajal v1 为种子

种子模型 Cajal v1 是一个共享编码器：它把每个细胞读成一组（基因，表达量）token，用注意力与循环混合专家块建立细胞表征，五个目标联合训练。演化从它的架构和训练配方出发，但每个候选都从随机初始化开始训练，不继承任何已训练的权重。

演化如何进行

  1. 提案。LLM 查看合约、组件库、基线和完整的候选谱系，提交一个候选：父代、假设、目标指标、相对种子的完整配置，以及可选的插件源码。它没有 shell、网络或数据访问。
  2. 校验。候选先过结构、取值范围和代码白名单检查，再在不挂载数据和 GPU 的 Linux 沙箱中做合成检查：张量接口、五个目标的梯度、参数更新和 checkpoint 重载。
  3. 训练与评估。通过校验的候选在沙箱中从随机初始化训练一个共享模型，一个 checkpoint 产出全部六个指标。
  4. 晋级与留档。按冻结的门槛判定是否晋级；所有候选，包括失败和未晋级的，都留在谱系中，可作为后续的父代。

插件只能使用 torch 张量代码；单文件不超过 32 KiB，总计不超过 128 KiB，模型不超过 2 亿参数。

两种演化方式

训练阶段的演化已经实现：改架构、组件、损失、优化器和训练配方，通过反向传播训练。推理阶段的演化已预留、尚未实现：不做梯度更新，例如用对照样本提取表征方向、定向修改少量权重（steering）。它需要读取已训练的模型，因此会作为另一种权重策略的 campaign 出现，同样先定义、再冻结。

晋级规则与证据

  • 任何指标相对父代的下降都不能超过 0.005。
  • 目标指标取父代相对最强对手最弱的一项（不在候选声明的目标内时，取声明目标中最弱的一项），候选在它上面必须同时比父代和固定参考高出 0.005 以上。
  • 联合前沿的排序必须变好：先比相对基线最弱的一项，再比平均相对增益。

当前 campaign 只有一个种子，结果标记为单种子探索性结果，不报告标准差，也不声称显著性。评估集会反复用作演化反馈，因此结果不是新的盲测；密封的测试集不可访问。

nanoBrain 不保证什么

  • 不保证演化一定找到更好的模型；“没有改进”是合法且会被记录的结果。
  • 冻结保证的是同一个 campaign 内规则不变，不保证规则本身合理；规则是否合理由人在定义阶段负责。
  • 插件代码的静态检查加操作系统沙箱是隔离手段，不是对任意 Python 代码的安全证明。

使用

git clone https://github.com/novaeve/nanobrain.git
cd nanobrain
python scripts/download_data.py        # 下载并校验数据
pip install -e '.[eval,scvi,dev]'

nanobrain                              # 只打印计划，不调用 LLM、不训练
nanobrain --freeze                     # 冻结 campaign，提交 campaign.lock.json
nanobrain --execute                    # 开始或续跑演化

完整流程需要 Linux、NVIDIA GPU 和 bubblewrap。定义新的 campaign、冻结规则、记录文件和退役检查的完整说明见白皮书。
